The Alert Engine (Garuda_web.py L853–1160) handles all notification and evidence-capture tasks that follow a confirmed danger detection. Entry is through trigger_software_alert (L994), which first acquires _mode_lock and skips execution if MODE_DND or MODE_IDLE is active; otherwise it sets _alert_active and _alert_end_time for a 3-second banner, then calls push_urgent_ws (L897) to broadcast a JSON alert payload to every connected WebSocket client. Concurrently, send_email_alert (L1023) delivers an SMTP notification to the configured admin address subject to a 60-second cooldown and the MODE_EMAIL_OFF flag. A separate path handles OTP delivery via send_otp_via_email (L853), used for admin login and password reset flows, while _send_tamper_email (L1061) is reserved for deadman watchdog violations. When evidence capture is requested, clip_start (L3268) and clip_stop (L3296) bracket a video segment; _encrypt_clip_aes256 (L1085) then encrypts the clip using AES-256-CBC with a key drawn from the EXFIL_AES_KEY environment variable, and _ssh_upload (L1111) combined with exfiltrate_clip (L1144) transfer the encrypted file to a remote server via paramiko SSH.
