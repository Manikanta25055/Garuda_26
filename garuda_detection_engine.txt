The Detection Engine (Garuda_web.py L1209–1365, app_callback) runs as a GStreamer pad probe on every frame that exits the HailoMuxer, giving it synchronised access to both the raw pixel buffer and the Hailo metadata tree. For each frame, get_numpy_from_buffer converts the buffer to a NumPy array and hailo.get_roi_from_buffer extracts the root HAILO_ROI object; all HAILO_DETECTION child objects are then iterated and filtered by a confidence threshold of 0.3 (DETECTION_THRESHOLD). Surviving detections are classified by label: objects matching the WATCH_LABELS set (Person / person) are logged to the persistent detection log with a 30-second per-label cooldown, while objects matching the DANGER_LABELS set (Knife, Scissors, Hammer) are counted via the _label_consec_frames dictionary. Once a danger label accumulates enough consecutive frame hits, trigger_software_alert is called, initiating the full alert pipeline. In parallel, the engine maintains _class_counts_today, _total_frames, and _detections_today counters that are exposed to the dashboard via the /api/state route, and the user_app_callback_class set_frame / get_frame interface is used to share the current annotated frame with the MJPEG and WebRTC streaming paths.
