The Detection Engine in Garuda_web.py (app_callback, L1209–1365) runs as a GStreamer pad probe on every frame that exits the HailoMuxer, giving it synchronised access to both the raw pixel buffer and the Hailo metadata tree. For each frame, get_numpy_from_buffer converts the buffer to a NumPy array and hailo.get_roi_from_buffer extracts the root HAILO_ROI object; all HAILO_DETECTION child objects are then iterated and filtered by a confidence threshold of 0.3 (DETECTION_THRESHOLD). Surviving detections are classified by label: objects matching the WATCH_LABELS set (Person / person) are logged to the persistent detection log with a 30-second per-label cooldown, while objects matching the DANGER_LABELS set (Knife, Scissors, Hammer) increment the _label_consec_frames counter and, once enough consecutive frames confirm the threat, call trigger_software_alert to fire the full alert pipeline. In parallel, _class_counts_today, _total_frames, and _detections_today counters are maintained for the dashboard, and the user_app_callback_class set_frame / get_frame interface shares the current annotated frame with the MJPEG and WebRTC streaming paths.

Cascade Architecture (garuda_cascade.py, standalone — not called by Garuda_web.py): garuda_cascade.py implements a three-stage inference pipeline designed for higher-accuracy person verification. A camera_thread (L328) or gst_camera_thread (L354) feeds raw frames into an inference_thread (L405) that runs three models sequentially: Stage 1 uses YoloNetwork (YOLOv8s, L255) to detect persons and objects and return bounding boxes; Stage 2 crops each detected region and passes it through ClassifierNetwork (MobileNetV2, L302) for fine-grained classification; Stage 3 optionally runs DepthNetwork (MiDaS, L315) for monocular depth estimation, enabled only when _depth_active() (L122) returns True, which itself depends on config and _is_night() (L118) for time-aware behaviour. A postprocess_thread (L481) consumes inference results, applies fast_rgb_spoof (L129) for liveness checking, and writes final verdicts, while TestMetrics (L157) tracks per-run FPS, frame drops, and verdict distribution for benchmarking and evaluation.
