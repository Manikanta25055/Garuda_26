The Logging Engine (Garuda_web.py L560–700, system_logs/) implements a multi-tier persistence strategy designed to balance write performance with durability. All active log streams — alert history, voice command log, system event log, and voice responses — are held in bounded in-memory deques that accept writes from the GStreamer callback, the voice daemon, the mode controller, and the alert engine without any I/O latency. A periodic flusher daemon thread drains these deques to disk at regular intervals, writing human-readable entries to three permanent append-only text files (perm_detection_log.txt, perm_system_log.txt, perm_voice_log.txt) and updating structured JSON state files (alert_history.json, config.json) in the system_logs/ directory. A log rotation pass removes entries older than 7 days to prevent unbounded disk growth, running either on the flush cycle or at startup via load_config. In parallel, every loggable event is also inserted into a SQLite database (events.db) with a microsecond-precision timestamp; the /api/events?since=T endpoint queries this database to let browser clients that were offline for an arbitrary duration catch up on missed detections, alerts, and state changes without requiring the server to hold a full event buffer in memory.
