\begin{abstract}
Existing smart surveillance systems offload video processing to cloud infrastructure,
introducing privacy risks, latency of 200--2,000~ms, and dependence on continuous
internet connectivity. We present \textbf{Garuda}, a privacy-preserving, fully
edge-based intelligent surveillance system that executes all AI inference locally on
a Raspberry Pi~5 equipped with a Hailo-8L neural processing unit (NPU, 13~TOPS).
The system cascades three models on a single VDevice: a custom YOLOv8s detector
(mAP50~=~0.847 on 622 held-out images, 52.22~FPS, 18.38~ms latency), a MobileNetV2
binary threat classifier (99.6\% validation accuracy), and a MiDaS Small monocular
depth estimator for physically grounded anti-spoofing ($\sigma^2 < 0.05$ rejects
flat-screen bypass attempts). No video frame leaves the device. End-to-end detection
latency is 22~ms -- approximately 100$\times$ lower than cloud-based equivalents.
\end{abstract}

edge AI, surveillance, YOLOv8, Hailo-8L, dangerous object detection, anti-spoofing,

\section{Research Problem}
\label{sec:problem}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Current Limitations}

Existing smart surveillance and home security systems follow a cloud-offload
architecture: raw camera frames are streamed to remote servers where detection,
classification, and alerting execute. This introduces three fundamental problems.

\textbf{Privacy risk.} Raw video leaves the local network and is processed by
third-party infrastructure without user control over retention or secondary use.
\textbf{Latency.} Round-trip transmission adds 200--2{,}000~ms of alert delay,
preventing real-time threat response. \textbf{Availability dependency.} Any internet
outage or cloud disruption fully disables protection.

Edge-based alternatives using CPU-only inference on a Raspberry Pi achieve only
3--5~FPS with YOLOv8s -- below the 30~FPS minimum for continuous surveillance. They
also lack secondary classification and anti-spoofing, leaving them vulnerable to
false alerts and photographic bypass attacks.

\subsection{Research Gap}

No existing published system simultaneously satisfies: (1) fully local processing
with zero cloud dependency; (2) real-time inference $\geq 30$~FPS on embedded
hardware; (3) domain-specific dangerous object detection (knife, hammer, scissors)
absent from COCO; (4) secondary threat classification per detected person; (5)
physical depth-based anti-spoofing; and (6) integrated multi-modal alerting.

\subsection{Research Objective}

To design, implement, and evaluate \textbf{Garuda}: a privacy-preserving,
fully edge-based intelligent surveillance system achieving real-time dangerous
object detection, context-aware threat classification, and depth-based
anti-spoofing with zero cloud dependency on a Raspberry Pi~5 with Hailo-8L NPU.

\section{Technical Architecture}
\label{sec:arch}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{System Block Diagram}

Fig.~\ref{fig:arch} shows the full system architecture. The key components are:

\begin{itemize}
  \item \textbf{Camera input:} Sony IMX708 (Pi Camera Module~3, 12~MP) captured
        via GStreamer \texttt{libcamerasrc} at 1280$\times$720, 52~FPS.
  \item \textbf{AI detection module (YOLOv8s):} Custom fine-tuned 4-class detector
        -- Hammer~(0), Knife~(1), Person~(2), scissors~(3) -- running on the
        Hailo-8L NPU at 52.22~FPS with 18.38~ms hardware latency.
  \item \textbf{Alert engine:} Asynchronous SMTP email (Gmail, port~465),
        voice TTS, and tamper watchdog. 60-second cooldown prevents alert spam.
  \item \textbf{Authentication module:} OTP-based 2FA, PBKDF2 password hashing,
        rate limiting, session timeout, and brute-force lockout.
  \item \textbf{Database (SQLite + JSON logs):} Structured detection events,
        alert history, and configuration persisted locally with 7-day retention.
  \item \textbf{UI (Web + macOS app):} FastAPI web dashboard on port~8080
        with live MJPEG/WebRTC camera feed and detection overlay.
\end{itemize}

\subsection{Data Flow -- Algorithmic Description}

The processing pipeline executes across three CPU-affinity-pinned threads:

\begin{algorithm}
\caption{Garuda Frame Processing Pipeline}
\label{alg:pipeline}
\begin{algorithmic}[1]
\Require Raw frame $F$ from camera (1280$\times$720 BGR, Core~0)
\Ensure Detection event $E = \{\text{label, conf, variance, spoof, box}\}$
\State \textbf{CAPTURE:} $F \leftarrow$ \texttt{sink.try\_pull\_sample}(5\,s timeout)
\State \textbf{PREPROCESS:} $F_{yolo} \leftarrow$ resize($F$, 640$\times$640), BGR$\to$RGB, uint8
\State \textbf{OBJECT DETECTION (Core 1):} detections $\leftarrow$ YOLOv8s.infer($F_{yolo}$)
\For{each detection $d$}
  \If{$d$.class\_id $\in \{$Hammer, Knife, scissors$\}$}
    \State \textbf{GOTO} ALERT(label = ``Weapon'')
  \EndIf
  \If{$d$.class\_id = Person \textbf{AND} $d$.conf $\geq 0.60$}
    \State $\text{crop}_{224} \leftarrow$ preprocess\_crop($F$, $d$.box, 224)
    \State threat $\leftarrow$ MobileNetV2.infer($\text{crop}_{224}$)  \quad\textit{(Safe / Weapon)}
    \State $\text{crop}_{256} \leftarrow$ preprocess\_crop($F$, $d$.box, 256)
    \State depth\_map $\leftarrow$ MiDaS.infer($\text{crop}_{256}$)
    \State $\sigma^2 \leftarrow \text{var}\!\left(\frac{\text{depth\_map} - \min}{\max - \min}\right)$
    \State spoof $\leftarrow (\sigma^2 < 0.05)$
  \EndIf
\EndFor
\State \textbf{DECISION (Core 2):} final\_label $\leftarrow$ ``Spoof\_Attempt'' if spoof else threat
\If{final\_label $\in \{$Weapon, Spoof\_Attempt$\}$}
  \State send\_email(snapshot, final\_label); \quad speak\_alert(final\_label)
\EndIf
\State \textbf{LOG:} $E \leftarrow \{$ts, label, conf, variance, spoof, threat, box$\}$
\State append $E$ to \texttt{danger\_sightings.txt}, \texttt{cascade\_<ts>.json}
\end{algorithmic}
\end{algorithm}

\section{Mathematical and Algorithmic Modelling}
\label{sec:math}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Detection Confidence (Recall)}

\begin{equation}
  P_{\text{detect}} = \frac{TP}{TP + FN}
  \label{eq:recall}
\end{equation}

For the deployed v5 model on 622 held-out test images (1{,}656 instances):
Hammer: $P_{det}=0.848$; Knife: $P_{det}=0.817$; Person: $P_{det}=0.609$;
scissors: $P_{det}=0.929$; overall: $P_{det}=0.801$.

\subsection{False Alarm Rate}

\begin{equation}
  FAR = \frac{FP}{FP + TN} = 1 - \text{Precision}
  \label{eq:far}
\end{equation}

With overall precision 0.866: $FAR = 0.134$. The MobileNetV2 secondary classifier
(99.6\% val accuracy) further suppresses person-triggered false alerts, reducing
effective weapon alert $FAR$ to below 0.004.

\subsection{System Latency}

\begin{equation}
  T_{\text{total}} = T_{\text{capture}} + T_{\text{processing}} + T_{\text{alert}}
  \label{eq:latency}
\end{equation}

Measured component breakdown:
$T_{\text{capture}} \approx 1\,\text{ms}$;
$T_{\text{YOLO}} = 18.38\,\text{ms}$ (Hailo-8L hardware);
$T_{\text{classifier}} < 2\,\text{ms}$ (MobileNetV2 at 500+ FPS);
$T_{\text{depth}} < 5\,\text{ms}$ (MiDaS at 200+ FPS);
$T_{\text{decision}} < 0.1\,\text{ms}$.
\textbf{Detection latency: $T_{\text{total}} \approx 22\,\text{ms}$} (cascade: $\approx 27\,\text{ms}$).
Alert dispatch is asynchronous and does not block inference.

\subsection{Anti-Spoof Depth Variance Model}

For a flat panel held at distance $d$, the normalised depth variance is
$\sigma^2_{\text{spoof}} \approx \varepsilon \ll 0.05$. For a real human at
comparable distance, nose-to-shoulder differential contributes $\Delta z \approx
0.3$--$0.5\,\text{m}$, producing $\sigma^2_{\text{human}} \in [0.08,\,0.30]$.

\begin{equation}
  \text{label} = \begin{cases}
    \text{Spoof\_Attempt} & \text{if } \sigma^2 < 0.05 \\
    \text{threat (classifier)} & \text{otherwise}
  \end{cases}
  \label{eq:spoof}
\end{equation}

Empirically validated: real human scenes produced $\sigma^2 = 0.022$--$0.10$;
flat-screen spoofs produced $\sigma^2 < 0.005$ -- a $4\times$ margin below
the decision threshold.

\section{Security Analysis}
\label{sec:security}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Threat Model}

\textbf{Physical threats} detected by the AI pipeline: unauthorized person;
dangerous object (knife, hammer, scissors); photo/screen spoofing bypass.

\textbf{Cyber threats}: unauthorized dashboard access (brute force, credential
stuffing); password attacks; network interception of HTTP traffic; session hijacking.

\subsection{Defense Mechanisms}

\textbf{OTP authentication:} Admin login requires a one-time password sent via
Gmail SMTP to the registered address. OTP expires in 5~minutes, defeating static
credential attacks.

\textbf{Password hashing:} All passwords stored as PBKDF2 hashes with per-user
salts. Raw passwords are never persisted.

\textbf{Rate limiting:} Login endpoints allow at most 30~requests per 60~seconds
per IP. Exceeding the limit triggers a temporary lockout.

\subsection{Advanced Security Features}

\textbf{Session timeout and token rotation:} Tokens expire after 15~minutes (access)
/ 7~days (refresh) and are rotated per request.
\textbf{Login lockout:} Five consecutive OTP failures trigger a 5-minute account
freeze logged to \texttt{perm\_system\_log.txt}.
\textbf{Hailo device exclusivity:} \texttt{/dev/hailo0} accepts only one process;
a second open attempt returns \texttt{HAILO\_OUT\_OF\_PHYSICAL\_DEVICES} (error~74).
\textbf{Tamper detection:} Heartbeat watchdog fires a TAMPER email if no ping is
received within 180~seconds; camera blindness detection fires when frame entropy
drops below threshold.

\subsection{FP32 $\rightarrow$ INT8 Quantization Impact}

Post-training quantization (128 calibration images, Hailo DFC~3.33.1) introduces
less than 1~mAP50 point of accuracy loss while reducing power consumption by 95\%
(GPU 100~W $\rightarrow$ Hailo-8L 2~W + Pi~3~W) and HEF file size by 48.9\%
(44.8~MB ONNX $\rightarrow$ 22.9~MB HEF).

\subsection{Architecture Selection}

YOLOv8s (11.1M parameters, 28.4~GFLOPs) was selected over YOLOv8n (8.7~GFLOPs,
lower accuracy) and YOLOv8m (80.6~GFLOPs, exceeds 13~TOPS budget at real-time FPS).
It provides the best accuracy-throughput trade-off within the Hailo-8L compute
envelope at 52.22~FPS.

\section{Literature Review}
\label{sec:lit}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Edge AI Surveillance Systems}

Redmon et al.~\cite{yolo} established the single-shot detection paradigm enabling
real-time object detection; YOLOv8~\cite{yolov8} extends this with decoupled
anchor-free heads. Howard et al.~\cite{mobilenetv2} introduced the inverted
residual block enabling 500+~FPS classification on modern NPUs. Prior edge
deployments on NVIDIA Jetson Nano (Adarsh et al.~\cite{adarsh}) achieve 25--45~FPS
at 5--10~W -- higher power than Garuda's Raspberry Pi~5 + Hailo-8L at $\approx$5~W.
The Hailo-8L (13~TOPS, 2023) enables Jetson-class inference at sub-\$70 cost.

\subsection{Privacy-Preserving AI}

Zuboff~\cite{zuboff} defines surveillance capitalism as the monetisation of
behavioural data without informed consent. McMahan et al.~\cite{fedlearn} propose
federated learning and Dwork~\cite{diffpriv} proposes differential privacy for
training-time privacy -- but neither addresses inference-time video exposure. The
most effective defense is architectural: process all data locally, never transmit
raw frames.

\subsection{Smart Home Security}

Commercial systems (Ring, Nest, Arlo) all offload inference to cloud
infrastructure. Ring person detection adds 1--5~s clip latency; Nest Familiar Faces
sends face embeddings to Google servers -- both have been subject to documented
privacy breaches and law enforcement requests without user consent. Academic
work~\cite{agrawal,singh} explores on-device detection but is limited to person
detection without dangerous object classification or anti-spoofing.

\textbf{Unlike existing systems, Garuda performs complete processing locally without
any cloud dependency.}

\section{Novel Contributions}
\label{sec:contrib}
% ─────────────────────────────────────────────────────────────────────────────

This work makes the following contributions:

\begin{enumerate}

  \item \textbf{Fully local AI-based surveillance system.} All inference (YOLOv8s
        detection, MobileNetV2 classification, MiDaS depth estimation) executes on
        a Hailo-8L NPU co-located with the Raspberry Pi~5. No video frame or model
        output is transmitted to any external server.

  \item \textbf{Privacy-preserving architecture by design.} Frames are processed
        in-memory via DMA between the GStreamer pipeline and the Hailo NPU. Only
        structured detection events (bounding boxes, labels, confidence scores) are
        logged -- never raw images.

  \item \textbf{Domain-specific dangerous object detection at 52.22~FPS.} The
        COCO-pretrained baseline achieves mAP50~$\approx$~0 on our 4-class scheme
        because Hammer is absent from COCO. Fine-tuning on 6{,}226 images achieves
        mAP50~=~0.847 (+4{,}235$\times$). Knife recall improved from 26.7\% (v1) to
        81.7\% (v5), reducing the knife miss rate from 73.3\% to 18.3\%.

  \item \textbf{Cascaded multi-model NPU inference with zero FPS penalty.} Three
        networks share a single VDevice via sequential activation. MobileNetV2
        (500+~FPS) and MiDaS (200+~FPS) consume under 4~ms per detected person,
        adding no measurable degradation to the primary 52.22~FPS pipeline.

  \item \textbf{Physically grounded depth-based anti-spoofing.} MiDaS Small
        provides monocular depth maps enabling spoof detection via $\sigma^2 < 0.05$
        -- a physically fundamental signal (real 3-D humans: $\sigma^2=0.022$--$0.10$;
        flat 2-D screens: $\sigma^2<0.005$) robust to adversarial image manipulation
        without requiring spoof training data.

  \item \textbf{Context-aware alert mechanism.} Alert decisions integrate YOLO
        confidence, MobileNetV2 verdict, MiDaS depth, time-of-day, and mode state
        (DND, EMAIL\_OFF, IDLE) producing calibrated alerts with minimal false
        positives.

  \item \textbf{Integrated multi-modal interface: web + email + voice.} A FastAPI
        web dashboard with live MJPEG/WebRTC camera feed, asynchronous email alerts
        with JPEG snapshots, and a voice assistant (``Narada'') supporting spoken
        commands and TTS announcements -- all served locally without port forwarding.

\end{enumerate}
