--------------------------------------------------
Metric Definitions
--------------------------------------------------
FPS (HW-only)     : Raw NPU throughput, no host I/O — theoretical upper bound.
FPS (Streaming)   : End-to-end including host DMA — closest to pipeline reality.
HW Latency        : Single-inference NPU latency (non-batched).
mAP (Float)       : COCO mAP@[0.5:0.95] of original FP32 model (pre-quantization).
mAP (INT8 HW)     : COCO mAP@[0.5:0.95] after INT8 quantization compiled to HEF.
                    This is what runs on Hailo-8L in production.
Quantization Drop : Accuracy lost due to INT8 quantization (Float - HW).

Note on Precision / Recall / F1:
  These are confidence-threshold-dependent metrics. Hailo does not publish them
  in the model zoo. To obtain them, COCO val2017 evaluation must be run on-device
  at a specific threshold (e.g. conf=0.25, IoU=0.45). See section at the bottom
  for the evaluation command to run when COCO val2017 is available.

Note on Power:
  hailortcli measure-power returned no data. Hailo-8L M.2 HAT on RPi5 PCIe does
  not expose a current-sense resistor via the hailortcli interface.
  Published TDP for Hailo-8L: 1.5 W (typical inference load).

--------------------------------------------------
To obtain Precision / Recall / F1 on-device
--------------------------------------------------
Requires: COCO val2017 images + annotations (~1 GB)

  # Download
  wget http://images.cocodataset.org/zips/val2017.zip
  wget http://images.cocodataset.org/annotations/annotations_trainval2017.zip

  # Evaluate using ultralytics (FP32 baseline for comparison)
  pip install ultralytics
  yolo val model=yolov8s.pt data=coco.yaml split=val

  # For INT8 HEF on-device evaluation, use Hailo Model Zoo eval pipeline:
  # hailomz eval --target hailo8l yolov8s

Results from this will give per-class AP, P@conf, R@conf, F1@conf curves.
