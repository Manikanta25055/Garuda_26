The Voice Assistant Engine, named Narada (Garuda_web.py L1534–1773), runs as a background daemon thread continuously listening on the system microphone via the speech_recognition library's sr.Microphone with automatic energy threshold adjustment. Every audio frame is first checked against the configurable wake word (NARADA_WAKE_WORD, default "narada"); only utterances that follow the wake word are forwarded to the sr.Recognizer for speech-to-text conversion. The transcribed text is handed to apply_rule_based_command (L1534), which attempts to match against a set of built-in rules and the user-defined CUSTOM_VOICE_COMMANDS registry before returning a result; if no rule matches, the text is sent to query_local_llm (L1587) which calls the Groq API (llama-3.3-70b-versatile) for natural-language intent resolution. Groq responses are structured JSON that _apply_llm_result (L1697) maps to concrete system actions such as toggling mode flags, composing emails, or querying system state. Both the rule-based and LLM-based paths write their input transcripts and output responses to the voice_assistant_log and voice_responses buffers, which are periodically flushed to perm_voice_log.txt.
